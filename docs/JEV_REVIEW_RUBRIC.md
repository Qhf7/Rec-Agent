# Jev v2 审核口径与题目版本

本文记录 2026 年 11 月 18 日的九题 v2 审核口径与对照设计。当前默认五题的发送内容和处置规则见 [Jev 问题清单](JEV_QUESTIONS.md)。

## 1. 先拆主张，再判断事实支持

一条文案可同时含多种表达。营销形式不免除客观主张的核验；普通建议或情绪化场景也不应机械要求数据库逐字记载。

| 表达类型 | 核验规则 | 示例与边界 |
| --- | --- | --- |
| 客观规格与属性 | 规格、材质、功能、资质必须有相应事实支持 | 2.5kg、原生木浆、显色、纯棉、少油烟 |
| 客观功效、量化或保证 | 明示和普通消费者明确理解的暗示均需足够事实 | 根治湿疹、续航30天、100%安全；不能靠“更安心”等主观词豁免 |
| 一般使用场景 | 与商品及已知场景相容即可，不自动视为实时个人事件 | 家庭开饭、通勤使用、陪娃活动；与实际适用人群冲突时仍需处理 |
| 主观感受或情绪收益 | 不要求数据库逐字记载，但不能暗示无依据的客观保证 | 撑住气场、下厨更从容；“根治疾病更安心”仍含医疗承诺 |
| 行动建议 | 祈使或邀请本身不证明也不要求用户已具有某需求 | 先补一袋、备着用，不等于“你已经缺粮” |
| 具体个人状态或事件 | 需要对应事实，不能从泛化标签跳推 | 你家纸用得快、你最近失眠、孩子正好穿140cm；有娃不证明这些状态 |

是否存在明确客观暗示，应按普通消费者对整句话的理解判断。例如“带娃一天有多累，让手环记下睡眠和心率”需检查是否暗示疲劳测量；心率与睡眠监测功能不能自行扩展成疲劳诊断。

## 2. Q2 四个选项的边界

| 回答 | 适用条件 |
| --- | --- |
| `supported` | 客观及暗示客观主张都有支持或被事实忠实蕴含；其余仅是相容场景、行动建议或没有额外承诺的主观表达 |
| `partial` | 核心客观卖点有依据，但有可独立删除的非核心客观断言没有依据；不能仅因存在建议或修辞就选此项 |
| `unsupported` | 可靠且足够的事实否定核心主张，或明确完备的功能/允许功效来源不支持核心宣称；开放资料没记载不自动等于已证伪 |
| `unverifiable` | 核验关键主张所需的事实源缺失、不可追溯或可靠来源彼此冲突，现有资料无法区分支持与不支持 |

先定位具体主张所需的事实：已由可靠证据证实的核心硬风险，不被无关资料缺失抵消；关键主张本身确因资料缺失而无法核验时选 `unverifiable`。可靠来源彼此冲突，与文案被可靠事实明确否定，是不同情形。

`coverage.complete`、`attrs_returned_complete` 只证明所需返回字段齐全，不证明 `functions` 是全部能力的封闭全集。规范商品资料中的 `functions` 是已知功能，不能用“列表未出现”直接证伪开放能力；`efficacy_claims_allowed` 是已提供的允许宣称证据，缺少相应条目也不能伪造一份完备认证来源。词表和 `rule_features` 只提供核验线索，不代替原始商品、功效或资质事实。核心规格与明确规格冲突时可选 `unsupported`；核心新功效缺少核验来源时可选 `unverifiable`，其中明确的医疗或安全风险仍由 Jev 的 Q3、Q6、Q7 分别判断。

纯修辞文案的事实支持不等于推荐质量优秀；吸引力、信息量、商品变体匹配应单独评估。儿童140cm SKU 与孩子是否合身也是选品适配问题，文案未声称合身时，不应把未知身高随意解释成它已说了错误事实。

## 3. 披露状态独立记录

| 状态 | 事实含义 | 本轮采用的审核口径 |
| --- | --- | --- |
| `visible`，flag=true | 已确认展示含披露 | 按正常内容风险审核 |
| `missing`，flag=false | 已确认缺少披露 | 业务要求披露时可建议补齐；不能与未知混淆 |
| `unknown`，flag=null | 展示配置尚未确认 | 记录配置待确认原因；**不单独阻止展示、不降低Q2事实支持、不单独触发人工或提高严重度** |

事实源完整性与披露状态分别提供给 Jev，模型据此判断具体内容风险，工作流保留配置注记。

Q3聚焦文字表达和客观暗示，Q5聚焦场景相容性，Q6给出内容资料或敏感疑点对应的安全判断。Q7是同一请求中的处置结论，不能假定读到了Q1–Q6答案。工作流最终 `decision` 原样采用 Jev 的Q7选择；`human_review` 为结果标签，当前流程不执行实际人工复核。

## 4. 新旧 Q2 对照设计

| 版本 | 用途 | 内容 |
| --- | --- | --- |
| `jev-questions-v1` | 历史冻结版本及离线回放 | 保留原九题定义逐字不变 |
| `jev-questions-v2-q2-legacy` | Q2对照A组 | 其他八题与v2完全相同，只有Q2使用冻结v1原文和选项说明 |
| `jev-questions-v2` | 九题版本、Q2实验B组 | 澄清Q2及披露独立口径后的九题 |

A/B使用相同候选、商品、事实、披露状态和模型，其余八题逐项一致。`question_schema_version` 与state内Q2定义随实验版本变化；候选和facts保持不变。两组都在同一套新披露规则下，单独检验Q2文字的影响。

历史v1与完整v2的比较包含多个问题变化，不能替代上述单因素Q2实验。实际提示词效果需要新调用；冻结响应离线回放用于复原原始模型判断，不代表重新运行了新题。

每个版本仍是9题：8道单选、1道严重度评分，选项标识兼容。v2 真实调用要求全部九题及有效置信度；旧三问和旧归档Q7格式只保留离线兼容，不能绕过真实调用的完整协议校验。

## 5. 验证边界

规则说明与合成样本的预期答案是开发测试参照，不能冒称独立人工金标。可选的离线模型质量评估由独立标注者按上述口径标注并仲裁分歧；开发、评估和留出测试按商品或模板分组，避免近似文案泄漏。这些标注属于模型评估材料，不是推荐与审核工作流中的人工复核环节。

有独立人工金标后，可报告模型高风险误判、正常表达误改写/误拦截、`human_review`标签占比、每题混淆矩阵和重复一致性。原始Q7、每题置信度、严重度与配置注记分别保存；不能只用更多expose判断改进，也不能把严重度当作违规概率。工作流的处置权归Jev，置信度和统计指标用于分析模型表现。

可以在项目根目录只读查看某一版本实际题目，不会调用模型：

```bash
python3 - <<'PY'
import json
from jev_protocol import build_jev_questions
print(json.dumps(build_jev_questions('jev-questions-v2'), ensure_ascii=False, indent=2))
PY
```
