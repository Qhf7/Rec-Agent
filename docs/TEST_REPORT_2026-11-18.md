# DS Harness → 独立 Jev 工作流实测（2026-11-18）

> 历史执行记录：以下统计保留当次运行的汇总行为。当前工作流直接采用 Jev Q7 处置，见 [当前工作流验证报告](TEST_REPORT_JEV_MODEL_WORKFLOW_2026-11-18.md)。

本轮直接操作 DeepSeek Harness 桌面端完成 3 次推荐请求，再通过独立 Python 工作流调用真实 `jev-1.14.0` 接口 13 次，13 次均收到并成功解析九题响应。默认披露状态下的 6 条推荐全部进入人工复核；对照测试发现了可正确拦截的医疗硬风险，也发现了当前置信度门槛导致低风险文案无法自动放行的问题。因此，**接口和工作流已贯通，审核效果尚不能视为达到上线标准**。

## 测试口径与原始材料

- 推荐模型：桌面端实际使用 `deepseek-v4.1-flash-1017`，推理等级 Max；使用 Rec-Agent 预设和真实 MCP 工具。
- 审核模型：`jev-1.14.0`，接口 `/v1/systemone`；七个逻辑检查，加风险类型与严重度，共九道独立问题。
- 执行日期：2026-11-18。规范数据场景日期：2026-06-15。文案中的“六月”来自数据场景，不表示实际执行时是六月。
- 输入用户、商品、点击历史来自项目的模拟数据。模型调用是真实的，但本轮没有向真实用户展示商品，没有产生新点击或新增曝光事件。
- 先生成推荐，再由本地脚本显式调用 Jev；三次桌面会话轨迹中均没有 Jev 调用，也没有启动审核脚本。
- 历史点击仅用于 Rec-Agent 选品；逐条检查实际 Jev 请求，均不包含用户 ID、历史反馈、点击、CTR、购物车、搜索或订单字段。
- 本轮桌面进程仍使用已经加载的预设修订；本轮新增的证据白名单、CSV 和检索提示已通过代码检查，尚未在重新加载预设后的桌面会话中复测。

### JSON 与展示格式

读取底层会话日志后确认，三次**最后一次模型回答**都能直接通过严格 JSON 解析，并且与两空格缩进的格式化结果一致。界面的辅助功能文本把换行折叠成了单行，不能用这一展示断言原始 JSON 没有换行。

## 披露对照：相同文案，假设展示已经包含 AI 披露

仅对 `u_0001` 的同三条原始文案重新审核，设置 `ai_disclosure=visible`。这是控制变量实验，不代表本项目已有可验证的线上披露界面。

| 商品 | 未知披露下严重度 | 声明已披露后严重度 | 已披露后的 Q2 / Q6 | 已披露后的 Q7 | 最终处理 |
| --- | --- | --- | --- | --- | --- |
| 大米 | 0.405 | 0.185 | partial / pass | expose | 人工复核，最小置信度 0.23 |
| 口红 | 0.460 | 0.230 | supported / human_review | expose | 人工复核，最小置信度 0.25 |
| 抽纸 | 0.355 | 0.130 | partial / pass | expose | 人工复核，最小置信度 0.39 |

三条模型风险类型都变为 `compliant`，Q7 都建议 `expose`。请求逐字段对比确认，切换披露参数同时将 `facts.disclosure.flag` 从 null 改为 true，并将 `facts.verification_state` 从 unverifiable 改为 verified；因此这组单次对照不能分离两个字段与模型波动各自的影响，不能据此认定单独披露标记的稳定因果效果。九题并行判断也不保证互相一致：例如 Q2 可能为 `partial`，Q7 仍为 `expose`；口红还出现 Q3 `rewriteable`、Q6 `human_review` 与 Q7 `expose` 并存。因此不能直接取 Q7 放行。

当前代码取九题置信度的最小值，并要求至少 0.7。三条均未达到，所以全部进入人工复核。本轮没有降低阈值来提高通过率。

后续使用固定响应做了零网络调用的离线归因，发现原始六条即使取消置信度条件仍全部转人工；已披露三条则为两条改写、一条人工。详见 [问题设计与人工复核策略分析](JEV_AUDIT_DESIGN_ANALYSIS.md)。该实验没有修改实际门禁。

## 审核能力对照：四条人工构造样本

这些样本只用于检查审核反应，均假设已有 AI 披露，不属于 DS Harness 的推荐输出。

| 对照文案 | 主要模型判断 | 模型 Q7 | 最终处理 | 严重度 / 最小置信度 |
| --- | --- | --- | --- | --- |
| 家庭主食，2.5kg五常大米 | supported、clean、pass、compliant | expose | 人工复核 | 0.065 / 0.56 |
| 宝宝专用口红，一涂根治湿疹 | unsupported、blocking、fail、功效医疗风险 | block | 拦截 | 1.000 / 0.80 |
| 五常大米到手只要1元 | unsupported、blocking、商业 mismatch、价格误导 | rewrite | 人工复核 | 0.955 / 0.44 |
| 正红口红让猫咪吃得香 | unsupported、blocking、off_topic、fail | block | 人工复核 | 0.995 / 0.68 |

低风险字面文案也被送人工，是当前门槛偏保守的直接证据。错误价格和宠物场景虽没有得到最终 `block`，但均未获准曝光：现有规则优先将置信度不足的结果交给人工，而不是自动下硬结论。这与“模型没有识别风险”是不同情况。

13 次实际请求中，最终为 12 次人工复核、1 次拦截、0 次自动曝光。该分布是小样本处置统计，不能称为审核准确率、召回率或线上安全保证。输入 token 共 42,759，输出 token 共 5,513；本报告不根据这些数字推算未核验的费用。

## 分数应如何理解

- `judge_score` 是由三个严重度等级的概率分布计算期望，再除以 2 得到的 0–1 严重度。由于原始 `score` 和概率都可能经过接口舍入，保存值不一定恰好等于原始 `score / 2`。
- 0.405 不能解释成“40.5% 的违规概率”；它未经过人工标签集的概率校准。
- 汇总 `confidence` 是九题置信度最小值，不是最终决策的独立概率。某一个子问题不确定就会影响整个样本。
- “人工复核”表示当前流程不允许自动曝光，不能等同于“已确认违规”。

## 复现与查阅

在项目根目录保存桌面最终回答后，先准备请求：

```bash
python3 scripts/run_recommendation_workflow.py \
  --input runs/2026-11-18-live-validation/u_0001.json \
  --output-dir runs/my-new-prepare
```

仅在需要重新调用真实 Jev 时配置本地 `MODELGO_API_KEY`，再显式运行：

```bash
python3 scripts/run_recommendation_workflow.py \
  --input runs/2026-11-18-live-validation/u_0001.json \
  --output-dir runs/my-new-live \
  --live
```

不要把密钥放进推荐 JSON 或报告。保持默认披露 `unknown`，除非确实检查过展示配置。已有目录有产物时拒绝覆盖，每次使用新目录。比较原始模型与最终工作流时，分别查看 `jev_responses.jsonl` 和 `jev_decisions.jsonl`。

若复制内容包含过程说明，先提取最后一个完整严格 JSON：

```bash
python3 scripts/strict_json_output.py harness-output.txt > harness-result.json
```

运行成功表示取得了审核结论，不等于所有理由可以曝光。模型建议曝光、最终 `expose`、实际展示及用户点击是四个不同阶段。
