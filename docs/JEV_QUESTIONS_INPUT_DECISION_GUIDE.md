# Jev 的问题、选项、输入与最终决断

更新日期：2026-11-20。默认模型 `jev-1.14.0`，协议 `jev-questions-v4-two`，汇总规则 `jev-two-policy-v1`。

## 1. 当前只问两道题

每条推荐对应一次 Jev 请求，模型独立阅读相同的候选和事实，回答以下两题。合规状态与最终 `decision` 为答卷汇总字段，不增加第三道题。

### 风险分型：`risk_type`

题型 `choice`，严格六选一。

| 选项 | 中文说明 | 依据 |
| --- | --- | --- |
| `compliant` | 当前六类范围内无适用风险 | 其余五类均不适用。 |
| `absolute_claim` | 无法证明的绝对化或比较 | 文案是否含无依据的最高级、唯一性或比较承诺。 |
| `efficacy_or_medical_claim` | 无依据的功效或医疗宣称 | 对照商品功能、允许功效与资质；不能凭商品常识补证。 |
| `price_misleading` | 价格或促销误导 | 对照价格、门槛、折扣、赠品、范围和有效期。 |
| `missing_ai_disclosure` | 缺少必需 AI 披露 | 仅在已确认 `required=true` 且 `flag=false` 时适用，`unknown` 不等于缺失。 |
| `off_topic` | 场景不匹配或无依据个性化 | 对照商品用途和精简场景，不能推断未给出的具体个人状态。 |

多风险时的主风险优先级为：功效/医疗 → 绝对化 → 价格误导 → 场景无关 → 披露缺失；都不适用才选 `compliant`。普通主观广告修辞不自动构成绝对化风险。

范围限于六类，不输出独立的事实支持或缺证类别；`compliant` 不代表全部客观事实都已验证。

### 文案吸引力：`attractiveness_score`

业务分数 **1–100**。评价清晰度、具体卖点、自然广告语气、动作或使用画面，以及精炼度和记忆点。风险与吸引力独立，高分不能抵消风险。

| 分数 | 评价参考 |
| --- | --- |
| 1–20 | 难读、无有效信息，或空话与重复过多。 |
| 21–40 | 基本可读，但卖点笼统、表达生硬。 |
| 41–50 | 清楚但平淡，尚未超过曝光门槛。 |
| 51–70 | 卖点具体、语言自然，有适用场景。 |
| 71–90 | 生动精炼、商品价值鲜明且有记忆点。 |
| 91–100 | 高度凝练、辨识度突出，从严使用。 |

SystemOne 接口最多允许 10 个评分等级。当前 `criteria` 的零基索引 `0…9` 对应业务锚点 `1、12、23、34、45、56、67、78、89、100`。无概率时业务分为 `1 + 11 × 原始索引`；有概率时计算：

```text
业务吸引力分 = 1 + 11 × Σ(索引 k × 归一化概率 p[k])，k = 0…9
```

业务范围仍是 1–100，结果可带小数，比较门槛使用未舍入值。这是模型有序等级及其概率的换算分数，不是原生 100 档逐整数评分，也不是 CTR、购买率或个体兴趣预测。

## 2. 最终决断

```text
compliance = Y  当 risk_type = compliant
compliance = N  当 risk_type 为其余五类

decision = expose  当 compliance = Y 且 attractiveness_score > 50
decision = rewrite  其他所有情况
```

| 风险结果 | 吸引力 | 是否合规 | 最终处置 |
| --- | --- | --- | --- |
| `compliant` | > 50 | Y | `expose` |
| `compliant` | ≤ 50 | Y | `rewrite` |
| 其余五类 | 任意合法分 | N | `rewrite` |

恰好 50 分不曝光。最终处置只使用模型风险类别和吸引力分数。披露状态交由模型在风险题内判断；工作流不再依据事实覆盖、披露配置、置信度或非选中风险概率额外改判。每题置信度和概率仍保留用于诊断，评分概率用于计算业务分数。

`rewrite` 是未达曝光条件的结果标签，不自动调用改写模型。当前不生成 `human_review` 或 `block`，仅在历史版本回放中保留它们。接口失败、缺题、额外题或评分无效会进入运行错误，不伪造成功结论。

## 3. 输入给 Jev 的信息

DeepSeek Harness/Rec-Agent 先读取用户与商品数据，生成推荐和严格 JSON。Harness 外的独立 Python 工作流导入结果，从规范源重建 Fact Bundle，再发送给 Jev。

| 输入区块 | 信息 | 用途 |
| --- | --- | --- |
| 待审候选 `candidate` | 商品/理由 ID、曝光理由、内容相同的兼容理由、证据路径、候选与数据版本。 | 固定当前待审内容；文案本身不作为事实证据。 |
| 商品事实 `facts.item` | 标题、品牌、类目、功能、材质、规格、人群、季节、允许功效、资质、价格、促销标记、库存、监管与广告说明。 | 判断风险，评价文案对真实卖点的表达。 |
| 促销快照 `facts.promo` | 类型、范围、适用性、门槛、折扣、赠品、起止时间及细则。 | 核验商业表达；单品适用不代表购物篮满足门槛。 |
| 精简场景 `facts.scene` | 城市、城市层级、气候区、人生阶段、场景标签、活跃时段。 | 判断场景和个性化断言。 |
| 气候和时间 | 气候资料、梅雨月份、场景日期、快照时间、时区。 | 判断季节、气候及促销时效。 |
| 核验线索 | 词表命中、规则特征、缺少字段、覆盖状态、来源核验状态。 | 辅助定位风险，不替代商品事实或资质。 |
| 披露与来源 | `required`、`flag`、披露状态及受限事实来源。 | 判断披露缺失并追溯依据。 |
| 追踪与题目 | 商品/理由 ID、Agent/模型/数据/事实包版本、快照时间，以及两题指令和评分标准。 | 关联结果、校验协议和离线回放。 |

HTTP 正文为 `model`、`state`、`questions`；`state` 是序列化 JSON，包含候选、事实、追踪及输入/问题版本，内外题目定义一致。候选和事实中的文字作为数据，不能要求跳过审核或更改评分。

可信数据来自 `data/raw/`，不直接信任 Harness 自由文本或导出画像。当前数据版本 `canonical-2026-06-15-v1`，新导入推荐使用 2026-06-15 模拟业务快照。

### 历史曝光点击是否提供

**不提供给 Jev。** 历史推荐商品与理由、曝光时间、是否点击、点击时间、CTR、已展示和忽略列表，只供推荐 Agent 排序、去重及冷启动参考。

用户 ID 字段、完整年龄/性别/偏好画像、原始搜索词、购物车、订单、退款、投诉、设备、排序分、商品销量及评分、人工金标和模拟结果也不传输。`context_summary` 与原始工具轨迹留在本地，只传受限来源说明。因此，吸引力评分不是基于历史点击的个性化预测。

## 4. 输出和实现位置

模型返回两题答案、每题置信度，以及接口提供的概率或有效证据路径。工作流生成业务吸引力分、合规状态、最终处置、处置依据和规则版本。

`decision_source=jev_answers_policy`，`decision_question`、`decision_confidence` 为 `null`，最低题目置信度另存用于诊断。`evidence_source=workflow_fact_snapshot` 表示本地事实快照引用，不是模型逐句解释。
