# Jev 问题设计、披露状态与人工复核策略分析

**历史分析（v1，已由后续 v2 实现更新）。** 本文保留当时的诊断和设计草案，不代表当前默认策略。最新口径见 [JEV_REVIEW_RUBRIC.md](JEV_REVIEW_RUBRIC.md)，最新验证见 [当前工作流测试报告](TEST_REPORT_JEV_MODEL_WORKFLOW_2026-11-18.md)。用户后续明确要求：披露未知不单独阻止展示，该要求已落实。

分析日期：2026-11-18。依据当时代码及保存的 13 次真实 Jev 响应。本次新增验证为离线分析，新增真实 API 调用为 0；当前发送问题、协议、置信度阈值和门禁均未修改。下文改写内容是设计草案，尚未成为实际请求。

## 结论

当前问题不只是“置信度阈值偏高”。已经确认存在三层设计不足：问题的判断边界不够清楚、事实可验证状态与展示披露状态耦合、多个重复且并行的判断通过统一最小置信度共同否决自动处理。

六条全人工符合当前代码，但不能据此认定六条文案都违规，也不能证明这些问题设计和阈值已经合理。应先澄清判断目标及处置含义，再做模型问题对照和策略校准。不能在这 13 条样本上调出一个“更好看”的曝光通过率。

## 1. 六条为什么全是人工复核

根据原始响应、Fact Bundle 与门禁代码逐项重算：

| 条件 | 原始六条命中数 | 能否单独导致人工复核 |
| --- | --- | --- |
| 披露 flag=null，导致整体 verification_state=unverifiable | 6/6 | 能 |
| 九题最低置信度小于 0.7 | 6/6 | 能 |
| Q6=human_review | 6/6 | 能 |
| Q7=human_review | 4/6 | 能 |
| Q2=partial | 6/6 | 不能；未触发人工门禁时走改写 |

这些条件重叠，不是互斥原因，不能相加计算各自贡献的人工比例。只改善 Q2 或只降低阈值，其他条件仍会触发人工。

六条 `coverage.complete=true`、`coverage.missing=[]`，商品资料没有因为披露未知而消失。`fact_bundle.py` 目前把“披露标记不明确”“缺工具轨迹”“字段覆盖不足”折叠为同一个整体不可验证状态。因此，整体不可验证不能解释为每条商品事实均不完整。

### 固定响应的离线门禁实验

在内存中的隔离门禁副本里，仅改变置信度比较阈值，保留所有模型答案和事实。当前 0.7 阈值的重算结果与原结果一致；没有调用模型或修改实际门禁。

| 固定响应组 | 当前阈值 0.7 | 取消低置信度条件后 |
| --- | --- | --- |
| 默认披露未知的六条真实推荐 | 6 人工 | 仍为 6 人工 |
| 披露已知的三条真实推荐对照 | 3 人工 | 2 改写、1 人工 |
| 字面正常大米文案 | 人工 | 曝光 |
| 三条人为构造的风险文案 | 1 拦截、2 人工 | 3 拦截 |

已披露组的大米、抽纸仍是 Q2 partial，所以取消置信度条件后进入改写；口红仍是 Q6 human_review，所以保留人工。

字面正常对照为“家庭主食，2.5kg五常大米”：Q2 supported 的置信度为 0.95，Q3 clean 的置信度为 0.56，Q6 pass、Q7 expose，最终仅因最低置信度 0.56 进入人工。这是门槛限制自动覆盖率的明确例子，但一个样本不能确定新的可靠阈值。

本机实验记录：`runs/2026-11-18-live-validation/policy-diagnosis/policy_diagnosis.json`。该实验只能隔离本地路由规则，不能预测改写问题后模型会如何回答，也不是新一轮线上审核。

## 2. Q2 问题本身有哪些不足

当前 Q2 要求“逐项核验曝光理由”，其中 supported 定义为“所有主张均有直接事实支持”。方向是对的，但缺少三类必要边界。

### 2.1 没有定义哪些表达属于待核验事实

| 表达类型 | 示例 | 建议审核口径 |
| --- | --- | --- |
| 客观商品属性 | 2.5kg、24包、原生木浆、显色 | 必须有对应字段支持 |
| 功效、量化或保证承诺 | 根治湿疹、续航30天、100%安全 | 必须有明确且足够的依据；营销语气不能免除核验 |
| 具体个人状态 | 你家纸用得快、你最近失眠 | 必须有相应且允许使用的个人事实，不能从一般标签推断 |
| 与商品相容的一般使用场景 | 家庭开饭、通勤使用 | 不等于宣称实时观测到了该事件；要核对场景与已知事实是否相容 |
| 行动建议 | 先补一袋、备着用 | 建议本身不等于断言已经缺粮或缺纸 |
| 主观情绪表达 | 撑住气场、下厨更从容 | 不机械要求数据库逐字记载，但仍须检查是否暗示可验证的功效、安全或保证 |

“主观修辞”不是一律放行。例如“根治湿疹，让你更安心”仍然包含明确医疗宣称；“带娃有多累，让手环记下……”也可能暗示手环能量化疲劳，应按普通消费者可能理解的客观含义判断。

如果题目不说明这些差别，模型可能将普通场景、建议和情绪收益也当作必须有数据库直接证明的客观事件。这是有依据的设计担忧，但当前标量响应没有具体词句解释，不能宣称已经证明每条 partial 都由这种误解导致。

### 2.2 选项之间的边界重叠

| 当前选项 | 定义中的歧义 |
| --- | --- |
| partial：部分主张缺乏支持 | “部分”可能恰好包括核心功效，也可能只是非核心描述 |
| unsupported：核心主张没有依据 | 可能是完整资料明确不支持，也可能只是关键资料没提供 |
| unverifiable：关键事实不足 | 与“核心主张没有依据”难以清晰区分 |

应区分“非核心内容可删除”“核心宣称被完整事实否定或不支持”“核验所需资料确实缺失”，并规定混合情形的优先顺序。事实来源彼此冲突，与文案被可靠事实证伪，也应分开；二者不是同一种冲突。

### 2.3 共享全局状态可能影响事实题

Q2 能看到披露标记和整体 `verification_state`，但问题没有明确“外部披露未知不等于商品主张无依据”。这为跨题混淆留下空间。

此前三条披露对照实际同时改变了两个字段：

```text
facts.disclosure.flag: null → true
facts.verification_state: unverifiable → verified
```

其他 state 内容一致。口红 Q2 从 partial 变为 supported，但两次置信度都很低。由于同时改变两项状态、每个条件仅调用一次，现有结果不能分离披露标记、整体状态和模型波动各自的作用。

## 3. 六条文案应如何看待

以下为人工按事实拆解，不是 Jev 返回的逐句理由，也不是正式人工金标。

| 商品 | 有支持的客观内容 | 需要澄清的表达与判断 |
| --- | --- | --- |
| 大米 | 宝妈/爱囤货标签、大米类目、2.5kg规格 | “先补一袋”是建议，不应因为没有“已经缺粮”的记录就判缺事实。大方向较清楚，具体 Q2 partial 原因未知。 |
| 口红 | 正红、哑光、显色、通勤女性适用人群 | “通勤”可为使用场景，“气场”为主观收益；不代表用户正在通勤，也不代表已证明用户心理状态。 |
| 抽纸 | 有娃、24包、原生木浆 | “家里纸消耗快”更接近个体消耗速度的断言，是值得删除或改写的部分；不能仅凭有娃确认。 |
| 手环 | 有娃、心率与睡眠监测功能 | “有多累”接“记下睡眠和心率”可能只是情绪场景，也可能暗示疲劳测量，需要明确暗示承诺口径。 |
| 短袖 | 广州、场景六月、纯棉、透气、儿童夏季服装 | “陪娃跑一夏”一般是使用场景，不宜自动认作耐久保证。140cm合身与否是缺失的选品适配信息；文案没有声称“一定合身”。 |
| 炒锅 | 家庭采购、不粘、少油烟 | “一家人等着开饭”可为叙事场景，“更从容”为主观收益；没有“你家现在”等实时断言时，不应强行要求家庭实时状态记录。 |

因此，六条并不应预先标成全部 supported，也不应凭现有低置信度 partial 就全部认定事实有错。应先把这些边界变成可复用的标注规则，再判断模型是否误判。

## 4. 其他问题也有职责重叠

| 设计点 | 当前问题 | 建议方向 |
| --- | --- | --- |
| Q1 身份与来源 | ID、版本、类型、字段路径已有代码校验；模型无法独立验证输入之外的真实来源 | 确定性校验由代码负责，模型的语义冲突检查另行界定 |
| Q3 表达风险 | 同时覆盖事实功效、价格、披露、跑题，与 Q2/Q4/Q5 重叠 | 聚焦文案表达及客观暗示风险，外部展示配置单独管理 |
| Q4 价格/促销 | 本轮均未涉及价格或促销，not_mentioned合理 | 保留；无商业表述时不因本题不适用给其他题增加风险 |
| Q5 场景相关 | 普通使用场景与具体个人状态未详细区分 | 判断相关性，避免将一般场景要求为实时事件证据 |
| Q6 人工门禁 | 同时整合缺失、冲突、类目及资质，范围很大 | 明确需人工解决的具体资料/敏感性条件，避免一出现类目就默认人工 |
| Q7 最终建议 | 与 Q6和代码汇总重复；并行请求中没有读到前六题答案 | 保留为独立建议时按交叉检查理解；真正汇总由代码完成 |
| risk_type | 缺少“披露未知”和一般事实支持不足等类别；单选还会隐藏并存风险 | 将模型风险类别与系统阻断原因分开记录；改枚举时需要协议版本化 |

九题并非九份独立证据。它们共享模型、文本和事实，职责也重叠，不能把多个相近答案当成独立投票。

## 5. 披露未知应如何处理

没有展示配置证明时阻止自动曝光是合理的，但应分别表达：

| 层次 | 示例状态 | 实际含义 |
| --- | --- | --- |
| 商品/场景事实核验 | verified、incomplete、conflicting | 能否核验文案中的客观主张 |
| 展示披露就绪 | visible、missing、unknown | 页面是否已满足业务披露要求 |
| 内容审核结论 | expose、rewrite、human_review、block | 文案内容如何处理 |
| 实际发布门禁 | 允许展示、等待配置核实、禁止展示 | 当前是否真的可向用户展示 |

这些为建议的分层含义，尚未新增实际输出字段。内容可以无明显风险，但因展示配置未知而暂不展示。若某个页面模板已由平台确认包含披露，可按有作用范围和版本的配置证明复用；不应让每条相同模板文案都重复占用人工审核。模板不适用、过期或未确认时仍阻止曝光。

`unknown` 与 `missing` 不能混用。前者需要核实配置，后者需要补齐配置；两者都不能为了提高通过率而直接填成 visible。

## 6. 九题最低置信度为何过于粗糙

当前实现是 `min(九题 confidence) >= 0.7` 才能继续自动处置。这是一条保守策略，不是已经验证的最终正确率。

- 各题类别数、任务难度与置信度分布不同；相同的 0.7 不自动具有相同可靠性。
- 核心功效是否有依据，与“低还是中风险”的细分等级不确定，被赋予了相同否决权。
- Q4 无商业表述、主要风险类别难以选择等与核心风险不同的疑点，也可能影响全局最低值。
- 即使核心题答案不变，增减题目也可能改变自动覆盖率。
- confidence 不等于所选类别的最大概率，也未被证明就是答对概率；最低值更不是系统最终结论的校准概率。
- 高置信度不代表低风险。例如模型很确定某文案违法；低置信度也不代表高风险，例如很难在“完全支持”和“部分支持”中区分正常文案。

本轮手环的 Q2 选择 partial，confidence=0.09，而 partial 的概率为 0.32。两项数值含义不同，不能把 0.09 解释成“仅有9%可能是部分支持”，也不能反过来当作“91%违规”。

建议评估按题目相关性、风险类别及具体决策所需证据聚合的策略。例如，强证据硬冲突是否应优先拦截、风险主类别有疑点但内容结论稳定时是否需要人工，都应分别定义。不要直接用平均置信度替代最低值，否则核心风险的不确定性可能被其他高分稀释。

现有代码先处理人工，再处理硬风险，所以宠物错配即使 Q7=block，也会因最小置信度0.68而最终转人工。它没有被放行，但是否应该占用人工，需要策略定义。对于没有明确事实证据、仅模型意见冲突的情况，也不能一概自动拦截。

## 7. Q2 改写草案：先明确口径，再验证效果

以下不是当前发送的问题，未改变生产协议。可以先保留九题及原枚举，只修改实验版本的解释范围，减少同时改动的变量。

### instructions 草案

> 仅核验曝光理由中可核验的客观主张及其向普通消费者明确暗示的客观含义。规格、材质、功能、允许功效、资质、量化或确定性收益、具体个人状态及事件均需相应事实支持。允许忠实转述，以及与商品和已知场景相容的一般使用场景；购买建议、祈使语气和纯主观情绪表达本身不要求数据库逐字记载，但不得借此暗示不存在的功能、疗效、安全保证或已发生的个人事件。不得从有娃等标签额外推断孩子尺码、疾病或实时状态。依据本题所需商品、场景、时间及商业事实作答，不因外部 AI 披露未知或缺失单独降低事实支持判断。不能把候选文本本身当作事实。

### criteria 草案与适用顺序

| 选项 | 建议边界 |
| --- | --- |
| unverifiable | 必需的事实源缺失、来源不可追溯或可靠来源互相冲突，以至无法核验关键主张。不能仅因披露状态未知触发。 |
| unsupported | 已有可靠、足够的相关事实明确否定核心主张，或明确完整的功能/允许功效来源不支持核心宣称。不能把开放资料里没有记载的内容自动等同已证伪。 |
| partial | 核心主张有依据，只有可独立删除的非核心客观断言没有依据；不是仅仅存在购买建议或主观措辞。 |
| supported | 可核验客观主张均有支持或可由事实忠实推出，其余只是相容场景、行动建议或未暗示额外客观承诺的主观表达。 |

混合情形先按具体主张检查：已经有明确可靠证据证明核心硬风险的，不因为其他无关资料缺失就把该硬风险抹去；关键主张本身因资料缺失无法判断时使用 unverifiable。以后若拆分“已证伪”与“未获支持”，需要同步修改枚举、门禁、样本标签和协议版本。

文案里若没有可核验的客观主张，应预先决定是否视为 supported 但推荐质量不足，或增设不适用状态；不能把“事实支持”与“文案是否有吸引力”混在一起。

## 8. 如何验证和校准

### 先制定人工口径

由两位标注者独立拆解主张、标注证据、风险和建议处置，分歧经仲裁。样本同时覆盖普通营销表达、字面事实、真实有依据的功效、虚构功效、价格冲突、资料缺失、一般场景、具体个人断言、敏感类目和商品变体适配。真实分布样本与专门风险挑战集分别报告。

不能预先强制把六条全部标为可曝光。抽纸的个体消耗速度、手环的潜在疲劳暗示等需要先由一致的业务口径决定。尺码适配另行标注，不能只靠曝光文案审核代替选品质量检查。

### 分离问题改写与代码策略

| 实验 | 固定项 | 改变项 | 主要验证目标 |
| --- | --- | --- | --- |
| Q2 题目对照 | 文案、事实、模型、其他题和披露状态 | 旧Q2 / 澄清后的实验Q2 | 正常修辞误判是否减少，虚构功效是否仍被识别 |
| 文案成对测试 | 商品事实、模型、题目、披露状态 | 字面事实→建议→主观收益→一般场景→明确个人断言→虚构功能 | 是否区分可接受营销与客观事实风险 |
| 披露独立测试 | 文案及商品事实核验状态 | visible / missing / unknown | Q2客观事实结论应稳定，发布门禁应按披露状态变化 |
| 资料缺失测试 | 同一句文案、披露状态 | 完整资料 / 必需资料缺失 | 是否正确使用 unverifiable |
| 汇总策略离线对照 | 已保存的原始模型回答 | min9 / 按题相关性和风险分类的候选策略 | 人工率、自动覆盖率与错放/误拒如何变化 |

披露独立测试要先将事实核验状态与披露状态分开表达；不能在实际生产中伪造 verified 或 visible。当前耦合结构下，仅切换披露参数不构成单字段独立实验。

提示词实验需要真正重新调用模型，并对相同条件重复测量；固定响应重放无法验证新问题的效果。问题和规则在开发集上确定，阈值在独立校准集上选择，最终在留出测试集上验收。类似文案、同商品改写或同用户模板应按组划分，避免近似样本泄漏。

### 验收指标

- 高风险漏放率，以及自动曝光集合中的高风险比例；二者分母不同，应分别报告。
- 正常文案被要求改写或拦截的比例，分别列出误改写与误拦截。
- 人工复核率、自动曝光覆盖率、自动处置覆盖率及人工处理量。
- 每题混淆矩阵、类别与场景分层结果、缺事实样本的处理、重复调用一致性。
- confidence 分箱可靠性与风险—覆盖率曲线；先满足可接受风险上限，再优化人工成本。
- 模型原始意见与工作流最终决定分栏，记录所有实际触发条件及阈值/协议版本。

本轮13条主要用于定位问题，不足以稳定估计错误率或给出新的业务阈值；特别不能用挑战样本中人为提高的风险占比替代生产分布。

## 9. 建议推进顺序

1. 冻结当前版本及实测材料，完善逐条件门禁归因，避免把“配置待确认”写成“文案违规”。
2. 明确 Q2/Q3/Q5 的判断边界和人工标注规则，将商品事实核验与披露就绪分开设计。
3. 先做问题版本对照，再选择风险与相关题驱动的汇总候选方案；保留明确硬风险的安全约束。
4. 用独立校准集与留出测试集选择策略，报告风险、误判和人审成本，不以提高 expose 数量作为唯一目标。
5. 新协议与门禁通过回归及真实对照后再替换当前版本；继续保持 Harness 生成与独立 Jev 审核的职责边界。
